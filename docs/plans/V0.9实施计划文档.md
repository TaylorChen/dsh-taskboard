# dsh-taskboard V0.9 实施计划

> 状态：待实施 · 基线 `v0.8.0` (`b786f4b`) · 目标 `0.9.0`
> 本文是实施依据。三项均为加法字段（`.default()` 模式），零破坏性。

---

## 一、背景

三个补全，都来自「任务作为领域对象还缺什么」的审视：

1. **执行者标注**。现状盲区：自动认领会领走所有 `open` 任务，包括「需要人拍板」
   的。状态机说「球现在在谁手上」，但没说「这个球应该由谁接」。`executor` 补上
   这最后一环——**意图**（人建任务时声明谁该接），不是权限。
2. **截止时间**。agent 模式不需要「计划开始」（agent 不由日历驱动），但**计划截止**
   是人的承诺，是有价值的调度信号——快到期的高权重、逾期可提示。不违背 ROADMAP
   排除甘特图/估时（那是工期估算，这是优先级信号）。
3. **备注**。`body` 是原始意图、活动流是结构化事件，缺**执行过程中的追加观察**
   （agent 干到一半的发现、人的补充说明）。`notes` 是追加式过程沉淀。

## 二、范围

### 做

| 编号 | 工作项 | 破坏性 | 依赖 |
|---|---|---|---|
| **W1** | `executor: 'agent' | 'human' | 'any'`——human 任务不被自动认领 | 否 | — |
| **W2** | `dueAt` 截止时间——调度权重 + 逾期提示 | 否 | — |
| **W3** | `notes` 追加式备注——过程沉淀 + `noted` 活动 | 否 | — |

### 不做（附理由）

| 不做 | 理由 |
|---|---|
| `plannedStartAt` 计划开始 | agent 不由日历驱动开始，按额度/就绪/调度工作 |
| 实际开始/结束时间字段 | 活动流 `claimed`/`done` 的 `at` 可推导，存字段是冗余 |
| 甘特图 / 工期估算 | ROADMAP 维持排除 |
| 权限体系（谁能认领） | `executor` 是意图声明，不是 ACL；单用户本地工具 |

## 三、工作项详述

### W1 · executor 执行者标注

**改动点。**

- `src/domain.ts` — `executor: z.enum(['agent', 'human', 'any']).default('any')`
- `src/service.ts` — `CreateTaskInput` / `UpdateTaskInput` 加 `executor?`；update 可改
- `src/autoclaim.ts` — 候选过滤加 `executor !== 'human'`（agent/any 可领）
- `src/tool.ts` / `src/routes.ts` — `executor` 参数/透传（enum 校验）
- 面板 — 卡片执行者徽标（agent/human/any）

**验收**

- [ ] `executor: 'human'` 的 open 任务不被自动认领
- [ ] `agent` / `any`（默认）可被认领
- [ ] 老记录读为 `any`（默认值兼容）
- [ ] 工具/路由可设置与修改

### W2 · dueAt 截止时间

**改动点。**

- `src/domain.ts` — `dueAt: z.number().int().nonnegative().nullable().default(null)`
- `src/service.ts` — 输入/存储
- `src/autoclaim.ts` — `selectClaimCandidate` 排序升级：
  优先级（urgent→low）→ **dueAt 升序（null 最后）** → createdAt 升序
- 面板 — 逾期（dueAt < now）显示警示、临近显示提示
- `src/tool.ts` / `src/routes.ts` — `due_at` 透传

**验收**

- [ ] 有 dueAt 且更早的任务优先被认领（同优先级）
- [ ] 无 dueAt 的任务排在有 dueAt 之后
- [ ] 面板显示逾期/临近提示
- [ ] 路由/工具透传

### W3 · notes 追加式备注

**改动点。**

- `src/domain.ts` — `notes: z.string().max(100_000).default('')`；活动动作加 `'noted'`
- `src/service.ts` — `CreateTaskInput.notes`（初始）、`UpdateTaskInput.note`（**追加**：
  `current.notes + '\n' + note`）；追加时活动流记 `noted`（from null, to note 预览）
- `src/tool.ts` — `task_update` 加 `note` 参数（追加一段）；`task_create` 加 `notes`
- `src/routes.ts` — PATCH 透传 `note`；POST 透传 `notes`
- 面板 — 卡片显示最近 notes（截断）；活动抽屉可见 `noted`

**验收**

- [ ] 追加不覆盖：两次追加 notes 都保留
- [ ] 追加触发 `noted` 活动条目
- [ ] 老记录 notes 默认 `''`
- [ ] 路由/工具透传

## 四、实施顺序

W1 → W2 → W3（互不依赖，按领域语义顺序）。

## 五、破坏性变更与回滚

全部加法字段 + 一个活动枚举值（`noted`，加法兼容）；`git reset --hard v0.8.0` 可回滚。

## 六、验证清单

**代码层**：check/build 全绿；单测覆盖 executor 过滤、dueAt 排序、notes 追加、
默认值兼容、noted 活动。
**集成层**：真实 E2E——human 任务不被认领（agent 任务被领）；dueAt 早的优先。
路由矩阵补 executor/due_at/note 透传。

## 七、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| human 任务被手动 agent 工具认领 | 低 | 工具 `task_claim` 不强制（模型显式认领是显式意图）；自动认领才过滤 |
| dueAt 排序过度 | 低 | 只做三级排序（优先级→dueAt→age），不做复杂加权 |
| notes 无限增长 | 低 | 上限 100k；面板截断显示 |
