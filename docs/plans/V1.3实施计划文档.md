# V1.3 实施计划文档 —— 体验（跨进程写安全 + 面板 UX）

> 本文是实施依据。v1.3 = 体验：两个进程会互相覆盖、归档的历史没有出口、卡片不能编辑、
> blocked 没有一键出口、done 只能一张张归档——这五件事必须有解。

## 一、问题

1. **跨进程写会静默丢数据**。JSON 后端每次写都整文件原子重写。两个进程共享一个
   `$DSH_HOME`（如 GUI + headless 并行）时，B 进程的快照落后于 A 的写入：B 的整文件
   重写会覆盖 A 的变更（包括 `nextTaskNumber` 计数器——可能 mint 出重复的短 id）。
   服务层 `expectedRevision` 只挡同进程内的并发，挡不住跨进程。
2. **归档没有出口**。v1.2 的 C1 承诺「恢复按钮存在」（风险表缓解项），但面板只有归档
   按钮，没有归档视图、没有恢复入口——归档=单行道。
3. **卡片不能编辑**。面板只能改状态/spec/打回；标题、描述、优先级、executor、截止
   都要靠工具或手工 HTTP。
4. **blocked 没有一键出口**。受阻卡片只能通过状态下拉移动；「解除阻碍」缺少显式动作。
5. **done 只能一张张归档**。`archiveAllDone()` 服务方法存在但没有 UI 出口。

## 二、设计

### C2 · 跨进程写安全（JSON 后端）

**为什么。** 「必然静默丢失」是不可接受的；把跨进程改写变成「可检测、可提示、可重试」。

**设计。** `createStore(domain, medium?)` 增加写前介质指纹校验：

- `medium.read(): string | null` 由插件注入：`dshHomePath('storages', 'taskboard.json')`
  直接读原文件。文件不存在（首写前）或解析失败（非 JSON 后端）→ 返回 `null` → 守卫关闭
  （诚实文档化为 JSON 后端专属）。
- 每次落盘写（`putTask`/`putProject`/`putActivity`/`deleteTask`/`deleteActivity`/
  `setGlobal`）前：把「领域内存状态」与「介质文件状态」做**规范化指纹**比较——
  记录按键排序、记录字段按键排序后再 JSON 序列化（消除键序/空白差异）。不一致 →
  `TaskboardError('concurrent-modification', '任务板在另一个进程中被改写；请刷新后重试')`。
- 路由把该错误映射为 HTTP 409；面板已展示服务端错误文案（无需新 UI）。
- 边界诚实：读→写窗口内另一进程恰好在写（TOCTOU）由后端 last-writer-wins 兜底，
  属于上游 seam，不在本包内解决；守卫把「必然静默丢失」收窄为「除非恰好同刻写入」。

**验收**

- [x] 单测：介质前进（模拟另一进程改写）→ 写被拒 `concurrent-modification`；
      介质与内存一致 → 放行；`medium.read()` 为 null → 守卫关闭
- [x] 真实 E2E：同一进程内手改介质文件（模拟另一进程写入）→ `create` 被拒；
      还原文件 → `create` 成功（另有 HTTP 层 409 校验）

### D1 · 面板归档视图

**为什么。** 归档 ≠ 删除，必须可回看、可恢复。

**设计（纯面板 + 已有路由）：**

- 面板头部加「只看归档」开关：开启时拉 `GET /board?archived=true`；归档卡片（都在 done
  列）显示「恢复」按钮 → `PATCH {archived: false}`（v1.2 路由已有）。
- `BoardTask` 增加 `archivedAt` 字段；归档卡片显示归档时间戳，恢复后回活跃视图。

**验收**

- [x] 开关切换拉取归档视图；恢复按钮把卡片移回活跃视图（路由层 E2E 已有，补面板）
- [x] 活跃视图与归档视图互斥显示

### D2 · 卡片编辑

**为什么。** 面板是全职操作面，改标题/优先级不该绕道工具。

**设计（纯面板；路由已支持这些字段）：**

- 每张卡片加「编辑」按钮 → 内联表单：标题、描述（body）、优先级、executor、截止
  （`due_at`，epoch ms）。
- 保存 `PATCH` 带 `expectedRevision`（沿用乐观并发，别的会话/进程改了会被 409 拒绝而非
  覆盖）。

**验收**

- [x] 面板可改标题/描述/优先级/executor/截止；保存后卡片刷新显示新值
- [x] 并发保护：携带陈旧 revision 的保存被服务端拒绝

### D3 · blocked 一键出口

**为什么。** 「解除阻碍」是高频动作，不应藏在状态下拉里。

**设计（纯面板）：**

- blocked 卡片加「解除阻碍」按钮 → `PATCH {status: 'open'}`；服务端离开 blocked 已清
  `blockedReason`，活动流记录移动。按钮旁保留原因展示。

**验收**

- [x] 一键从 blocked → open；原因被清除；活动流记录

### D4 · 一键归档全部已完成

**为什么。** `archiveAllDone()` 没有出口；done 列清空应该是点一下的事。

**设计：**

- 新增 `POST /api/taskboard/archive-done` → `{ archived: n }`。人类发起的治理写，PANEL
  actor，无审批（与单条归档一致）。
- done 列头「归档全部」按钮，两段式防误触：第一次点击变为「确认归档全部？」，再次点击
  才执行。

**验收**

- [x] 路由返回实际归档数量；done 列清空（未归档的 done 卡片全部消失）
- [x] 无 done 卡片时按钮禁用

## 三、实施顺序

C2 → D1 → D2 → D3 → D4。（先安全，再视图出口，再编辑，再单向动作出口，最后批量。）

## 四、破坏性变更与回滚

全部加法：`createStore` 可选参数、新路由、面板按钮。`git reset --hard v1.2.0` 可回滚。

## 五、验证清单

**代码层**：check/build 全绿；C2 守卫单测（拒写/放行/关闭三态）+ 规范化指纹单测；
D4 路由单测（归档数、空列幂等）。
**集成层**：真实 E2E——C2 手改介质被拒后还原可写；`POST /archive-done` 清空 done 列。
**上屏层**：3099 演示实例重启后人工核对 D1–D4 面板（归档视图/恢复、编辑表单、
解除阻碍、归档全部）。

## 六、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 指纹校验读文件开销 | 低 | 单 JSON 文件很小；仅写路径一次读 |
| 非 JSON 后端守卫失效 | 低 | 文档化为 JSON 后端专属；provider 返回 null 即关闭 |
| TOCTOU 残留窗口 | 低 | 诚实文档化；后端 CAS 属上游 seam |
| 误触归档全部 | 低 | 两段式确认按钮 |
| 面板编辑破坏卡片布局 | 低 | 内联表单沿用 spec 编辑器模式 |
