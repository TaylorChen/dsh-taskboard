# V1.4.2 实施计划文档 —— 新建/编辑弹窗统一

> 补丁级 UI 迭代：新建任务与编辑共用同一个弹窗，字段完全一致，新建时内容为空。

## 一、问题

现状确认：**新建**只收「标题 + 优先级」（内联小表单），**编辑**弹窗收 5 项
（标题/描述/优先级/executor/截止）——信息不一致。服务端 POST 路由本就支持全部字段，
缺的是面板的统一入口。

## 二、设计

- 移除列内联新建表单（`composingIn`/`draftTitle`/`draftPriority`/`submitDraft`）。
- 编辑弹窗升级为**统一任务表单弹窗**（`formDraft`，mode: edit | create）：
  - **编辑**：加载卡片值，头部 `编辑 <key>` + `项目 · 状态`；保存 PATCH + revision。
  - **新建**：字段全空，头部 `新建任务 · <目标列>` + `项目归属 · 目标列`（目标列由点击
    的 `+` 决定；blocked 列无 `+` 直达，归为 draft——受阻是 agent 报告，需原因）；保存
    POST（body/priority/executor/due_at/status 全带）；若处于项目过滤视图，新任务落到
    该项目，否则服务端默认第一项目。
- 保存按钮文案随模式：`创建` / `保存`。

## 三、验收

- [x] 点击任一列 `+` 弹出与编辑相同的弹窗，字段全空
- [x] 新建 POST 携带 body/priority/executor/due_at/status（curl 实测全通）
- [x] 编辑语义不变（PATCH + expectedRevision，409 不覆盖）
- [x] check/build 全绿；上屏核对（3099 实例）

## 四、破坏性变更与回滚

纯面板改动，无 schema/路由变化（新增 `projectId` 透传是既有路由能力）。
`git reset --hard v1.4.1` 可回滚。
