# V1.6 实施计划文档 —— 协作闭环（实时推送 + 有界重试 + 心跳可见 + 搜索筛选）

> 本文是实施依据。v1.6 = 协作闭环：看板不再「等刷新才知道变化」、失败不再「纯人工
> 处理」、执行中不再「黑盒」、找任务不再「靠肉眼」。依据 docs/功能缺口与新增建议.md。

## 一、范围决策

路线图的 V1.6 = P0 协作闭环六项。其中**项目生命周期**（建/改名/迁移，修复死功能 E1）
与**评论线程**（notes 升级为线程视图 + agent 侧评论）各自独立且偏产品化，**顺延至
V1.7**；本版聚焦四项有强感知、可端到端验证的核心：

| 项 | 内容 | 对应缺口 |
|---|---|---|
| C1 | 实时推送（SSE + 面板 EventSource） | P0-1 |
| C2 | 有界自动重试（retry-as-budget，幂等记录） | P0-3 |
| C3 | mid-task 心跳与进度可见（heartbeat 事件 + 面板存活时长） | P0-2 |
| C4 | 搜索/筛选（文本 + 标签 + 优先级，面板侧） | P0-5 |

## 二、设计

### C1 · 实时推送（SSE）

**为什么。** 面板不刷新就看不到别的会话/agent 的变更——协作的时延即断层。

**设计。** 路由 `GET /api/taskboard/events`（SSE）：
- 监听 `domain/changed` 事件（autoclaim 驱动已在用），每次变更向所有连接推送
  `event: changed` + 载荷（表/键/操作）；SSE 规范心跳注释每 25s；连接关闭即清理。
- 面板：挂载时 `new EventSource('/api/taskboard/events')`，收到 `changed` 后
  **防抖重载看板**（500ms）；EventSource 自带断线重连。归档/项目过滤状态不受影响
  （只触发 reload，视图状态保持）。
- 路由层确认宿主 webserver 允许流式响应（`ServerResponse` 直接写块）。

**验收**

- [ ] 真实 E2E：连接 events 端点 → 另做一次写 → 流内收到 changed 事件（node fetch 流式读）
- [ ] 单测：路由注册存在；面板 EventSource 逻辑 typecheck

### C2 · 有界自动重试

**为什么。** 瞬态失败（限流/超时/环境抖动）不该惊动人；无界重试又会烧预算——retry-as-budget。

**设计。** autoclaim 行配置 `autoRetry: { maxRetries: number (默认 0=关), backoffMs: number (默认 30_000) }`：
- settle **error** 路径：统计该任务已有重试次数（notes 中 `retry n/max` 计数）→
  未达上限：`update(status: 'open', note: 'retry <n>/<max>')`（释放认领，v1.5 已支持
  离开 in_progress 释放）+ 记录活动；达上限：照旧 settle blocked，reason 附
  `after <max> retries`。
- 幂等：每次重试是**全新子代理会话**，失败子代理的副作用由失败方负责（与首次执行
  同语义）；重试次数以 notes 计数为准（活动流可审计）。
- 重试回 open 后由 auto-claim 自然再认领（无需额外唤醒）。

**验收**

- [ ] 驱动单测：error settle + autoRetry → 任务回 open + note retry 1/2；再次 settle error → blocked（附 retries 信息）；completed 不受影响
- [ ] 真实 E2E：autoRetry 开启下真实派发失败 → 回 open → 再认领（驱动级验证计数）

### C3 · mid-task 心跳与进度可见

**为什么。** 执行中的子代理是黑盒（只有 settle）；OpenClaw 用 heartbeat/execution_updated。

**设计。**
- 驱动：执行记录挂 `setInterval` 心跳（`heartbeatMs` 配置，默认 10 分钟，unref），
  每跳 `recordActivity('noted', 'heartbeat: running <n> min')`——活动流证明存活；
  settle/cancel 时清除定时器。
- 面板：in_progress 卡片执行徽标已显示运行时长；活动抽屉可见心跳条目（无需改动或
  微调文案）。

**验收**

- [ ] 驱动单测：短 heartbeatMs 下派发中任务产生心跳 noted 条目；settle 后停止
- [ ] 面板 typecheck

### C4 · 搜索/筛选

**为什么。** 看板一大，找任务靠肉眼；UI 标配能力。

**设计（面板侧，无 schema/路由改动）：**
- 统计条下方加搜索框（匹配 key/标题/正文，大小写不敏感）+ 标签/优先级筛选（多选下拉
  或 checkbox 组，从 board.tasks 客户端过滤）。
- 过滤与项目/归档视图叠加；空结果显示「无匹配」。

**验收**

- [ ] 面板逻辑 typecheck；上屏核对（3099 实例）
- [ ] E2E 无（纯客户端，纳入上屏核对）

## 三、实施顺序

C1 → C2 → C3 → C4。（先让变化可见，再让失败自愈，再证明存活，再找得到。）

## 四、破坏性变更与回滚

C1/C3/C4 纯加法（新路由/新配置/面板）；C2 新增 autoclaim 配置 `autoRetry`（默认关，
行为不变）。`git reset --hard v1.5.0` 可回滚。

## 五、验证清单

**代码层**：check/build 全绿；C2 驱动单测（重试计数/上限/幂等语义）、C3 心跳单测、
C1 路由单测。
**集成层**：真实 E2E——SSE 收到 changed；autoRetry 失败回 open 再认领。
**上屏层**：3099 实例核对搜索/筛选、心跳条目、SSE 自动刷新。

## 六、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 宿主 webserver 对 SSE 有缓冲/关闭 | 中 | E2E 流式读实测；不行则降级为 10s 轮询（计划注明） |
| 自动重试烧预算 | 中 | maxRetries 默认 0（关）；retry-as-budget 文档化 |
| 心跳刷屏活动流 | 低 | 默认 10 分钟一跳；保留上限裁剪 |
| SSE 连接数/事件风暴 | 低 | 单板单面板，防抖 reload |
