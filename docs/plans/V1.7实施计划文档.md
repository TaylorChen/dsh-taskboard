# V1.7 实施计划文档 —— 生命周期与流水线（项目 CRUD + 评论线程 + 任务链）

> 本文是实施依据。v1.7 = 让看板成为「活的组织」：项目能建能迁（修复 v1.4 死功能 E1）、
> 任务上有讨论（线程）、完成能自动派生下一步（流水线）。依据 docs/功能缺口与新增建议.md。

## 一、范围决策

路线图 V1.7 = 生态接入（MCP/webhook/任务链/checkpoint）+ 上轮顺延（项目生命周期/评论
线程）。**MCP server、签名 webhook、checkpoint 恢复三者各自需要宿主级能力验证，集中
在本版会导致验证失真**——顺延至 V1.8（计划注明）。本版聚焦三件可端到端验证的：

| 项 | 内容 | 对应缺口 |
|---|---|---|
| P1 | 项目生命周期：建/改名/删除 + 任务迁移项目 | E1 死功能根因 |
| P2 | 评论线程：任务线程视图 + 面板评论输入（notes 升级） | P0-4 |
| P3 | 任务链：`nextTask` 完成自动创建下一任务（幂等） | P1-9 |

## 二、设计

### P1 · 项目生命周期

**为什么。** `task_projects` 只列不建，E1 项目过滤是死功能；多项目是产品化的地基。

**设计。**
- 服务：`createProject(name)` / `renameProject(id, name)` / `removeProject(id)`（非空
  项目拒绝删除，返回任务数提示）；`UpdateTaskInput` 增加 `projectId`（迁移任务，校验
  目标存在）。
- 路由：`POST /api/taskboard/projects`（建）、`PATCH /api/taskboard/projects/<id>`
  （改名）、`DELETE /api/taskboard/projects/<id>`（删，非空 409）；task PATCH 接受
  `project_id`。均为 PANEL 写（人发起的治理写，与归档同语义，无审批）。
- 面板：项目下拉旁加「新建」小表单（弹窗复用任务弹窗的样式模式）；项目管理入口
  （改名/删除）放项目下拉内（悬浮菜单或小弹窗）。
- 迁移任务：卡片编辑弹窗 meta 行加「迁移到项目」下拉（或独立操作）；PATCH project_id。

**验收**

- [x] 单测：建/改名/删（空与非空）服务方法；任务迁移校验；路由参数
- [x] 真实 E2E：HTTP 建项目 → 建任务落入新项目 → 迁移 → 项目过滤正确 → 非空删除 400（12/12 PASS）

### P2 · 评论线程

**为什么。** notes 是单向追加；agent 的 retry/heartbeat/证据都在活动流里但没有「讨论」
视图，人与 agent 的往来不可读。

**设计。**
- 面板卡片加「评论」按钮 → 活动抽屉改为**线程视图**：列出该任务全部 `noted` 活动条目
  （actorLabel + 文本 + 时间），并附输入框追加评论（PATCH note，带 revision）。
- 线程数据 = 活动流 noted 条目（actor/时间完整）；`task.notes` 保持持久文本不变
  （派发 prompt 仍引用它，重试/心跳语义不变）。
- agent 侧评论：子代理完成后的证据 summary 已在证据区；v1.7 不新增子代理中途发言
  （需 checkpoint，顺延 V1.8）。

**验收**

- [x] 单测：noted 活动条目带 actor/actorLabel/时间（既有）；追加评论走既有 note 路径
- [x] 上屏：3099 实例线程视图 + 评论输入框（playwright 确认）
- [x] E2E：HTTP 追加 note → 活动流 noted 条目出现

### P3 · 任务链

**为什么。** 完成一件事自动派生下一件是流水线；dependsOn 只阻塞不触发。

**设计。**
- 领域：`nextTask: { title, body?, acceptanceCriteria[], contextRefs?, definitionOfDone? } | null`
  （加法字段，默认 null）；工具/路由透传 `next_task`。
- 服务：任务进入 `done` 时若 `nextTask` 非空 → 自动创建子任务（同项目，spec 带入），
  父任务 `nextTask` 清空 + 追加 note `chained → <key>`（幂等：清空即不会重复创建）；
  子任务创建为 `open`（spec 完整）或 `draft`（无 criteria）。
- 创建是系统写（driver/服务自动化，与 autoClaim 同立场），不触发审批。

**验收**

- [x] 单测：done 时创建子任务 + 幂等（重复确认不二次创建）+ nextTask 清空
- [x] 真实 E2E：建父任务带 nextTask → 确认完成 → 子任务自动出现且字段正确（含幂等）

## 三、实施顺序

P1 → P2 → P3。（先让项目活起来，再让人机可讨论，再让工作自动派生。）

## 四、破坏性变更与回滚

加法：`nextTask` 字段（`.default(null)`）、`UpdateTaskInput.projectId`、新路由/工具
参数、面板线程视图。`git reset --hard v1.6.0` 可回滚。

## 五、验证清单

**代码层**：check/build 全绿；P1 服务/路由单测；P3 服务单测（链创建/幂等）。
**集成层**：真实 E2E——项目建/迁/删；note 追加出现于活动流；父任务 done → 子任务出现。
**上屏层**：3099 实例核对项目新建/迁移、评论线程、链创建。

## 六、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 删除项目误删任务 | 高 | 非空项目拒绝删除（409 + 任务数）；文档明示 |
| 任务链无限递归 | 中 | nextTask 单层派生，子任务不再自动检查自身 nextTask（仅在 done 时创建，且用户可控制） |
| 线程视图与活动抽屉冲突 | 低 | 抽屉升级为线程（保留时间线语义） |
| 迁移项目破坏统计/过滤 | 低 | projectId 过滤本就按字段；迁移即改字段 |
