# V1.5 实施计划文档 —— 度量与协作闭环（看板统计为中心）

> 本文是实施依据。v1.5 = 度量：看板从「计数条」升级为「真统计」——比率、平均、
> 趋势、卡点、代价全部可查；同时补上两个协作断点（notes 对 agent 可见、token 用量
> 落库）。依据 docs/产品化Review.md。

## 一、问题

1. **看板统计缺失**。面板只有 E2 实时计数条（`filter().length` 快照），没有比率/
   平均/趋势/卡点/代价；全项目无 `/stats` 端点。竞品 agent-board 至少有三项
   Board Stats（完成率/平均时长/stuck），我们为零。
2. **数据地基已存在**。活动流每条 `{action, from, to, at}` 记录全部状态转换
   （created/status/blocked/claimed/completed/edited/noted）——一切时间度量可推导，
   零采集成本，只差计算与呈现。
3. **两个协作断点**。① 实际 token 用量从不落库（只有预算，无法度量代价）；
   ② notes（含打回原因）不在派发 prompt 里——人的指示对执行 agent 不可见。

## 二、设计

### S1 · 看板统计（中心）

**为什么。** 「花了多少时间/代价、一次做对率、卡在哪」是 agent 协作与度量的核心。

**设计。** 新增 `TaskboardService.stats(filter?)` + 路由 `GET /api/taskboard/stats`，
全部由活动流 + 当前板推导：

- **比率**：完成率（done / 历史任务）、重做率（打回次数 / 完成任务数，bounce =
  status→draft 且带 note）、agent 成功率（settle completed / completed+error）、
  逾期率（dueAt 过期未完结占比）。
- **平均**：cycle time（首次 in_progress→done）、lead time（created→done）、
  等人时长（awaiting_human 驻留合计）、受阻时长（blocked 驻留合计）——逐状态
  驻留 = 活动流同状态相邻片段求和；活动流有保留上限（50/任务），老任务缺失的
  早期片段按可用数据计算（文档注明）。
- **趋势**：近 7/30 天每日完成数与新建数（吞吐）。
- **卡点**：滞留任务列表（in_progress / awaiting_human / blocked 超过阈值分钟数，
  阈值可配 `statsStuckMinutes`，默认 in_progress 120 / 等人 1440 / 受阻 720）+
  最老未完成 top5。
- **代价**（依赖 S2 落库）：总/平均 token、预算超支任务数；S2 未上线时该项为
  `null`。

**呈现**：面板「概览」计数条保留，其下新增**统计区**（可展开/收起）：比率一排 +
趋势迷你条（7 天完成柱状，纯 CSS）+ 卡点列表（警示色）。不做完整 BI。

**验收**

- [ ] 单测：驻留时间推导（含打回分段求和）、比率计算、趋势窗口、卡点阈值
- [ ] 真实 E2E：制造已知历史（建→完成、打回→完成、受阻）后 `/stats` 数值正确

### S2 · 实际 token 用量落库

**为什么。** 预算只有上限，没有消耗；代价度量缺数据。

**设计。** settle 时记录实际用量：派发时 `subagents.start` 的 run 结果或
`ctx.tokenMeter` 在 settle 时刻的会话消耗增量。加法字段
`tokensUsed: number | null`（默认 null），settle completed/error 时写入（子代理
会话总消耗 - 派发前基线）；`stats` 的代价维度消费它。工具/路由不暴露（内部度量）。

**验收**

- [ ] 单测：settle 记录 tokensUsed；未记录时 stats 代价为 null
- [ ] 真实 E2E：一轮真实派发后 tokensUsed > 0（驱动级验证）

### S3 · notes 对执行 agent 可见

**为什么。** 打回原因/过程备注在 notes 里，但派发 prompt 不引用——人的指示
agent 永远看不到，协作是断的。

**设计。** `renderDispatchPrompt` 增加 notes 段（引用最新 notes，`clip` 有界）；
bounce 原因本来就在 notes（`note: "bounce: …"`），自动进入执行上下文。面板无改动。

**验收**

- [ ] 单测：带 notes 的任务派发 prompt 含 notes 文本；超长被截断
- [ ] 真实 E2E：打回后重派，子代理收到原因（驱动级）

## 三、实施顺序

S1 → S2 → S3。（统计中心 → 代价数据 → 协作闭环。）

## 四、破坏性变更与回滚

加法：`tokensUsed` 字段（`.default(null)`）、`/stats` 路由、面板统计区。
`git reset --hard v1.4.2` 可回滚。

## 五、验证清单

**代码层**：check/build 全绿；S1 驻留/比率/趋势/卡点单测；S2 settle 落库单测；
S3 prompt 注入单测。
**集成层**：真实 E2E——已知历史下 `/stats` 数值正确；真实派发 tokensUsed > 0；
打回后重派收到原因。
**上屏层**：3099 实例重启核对统计区（比率/趋势/卡点）。

## 六、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 活动流保留上限导致老任务度量不全 | 低 | 按可用数据计算，文档注明口径 |
| 趋势图复杂化 | 低 | 纯 CSS 7 天柱状，不做图表库 |
| tokensUsed 口径（会话基线漂移） | 低 | 派发时记录基线，settle 时差量；文档注明近似 |
| 统计端点被滥用（大板性能） | 低 | stats 只扫活动流（50/任务上限），数量有界 |
